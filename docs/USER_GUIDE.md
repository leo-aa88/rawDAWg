# rawDAWg — User guide

**rawDAWg** — *Less thinking. More noise.* This guide describes what the current build (0.1.0, release candidate work in progress) actually does. Open gates and known limits are listed in `PROGRESS.md`.

## Quickstart (ten minutes)

1. **Install and start.** Install the package for your system (see **Installing** below) or build from source, then start rawDAWg. It opens a new project with one playable **rawDAWg Synth** channel. If no audio device can be opened, the status bar says **Audio unavailable**: everything except playback still works.
2. **Play.** Hold `Z X C V B N M` (white keys) and `S D G H J` (black keys) on your computer keyboard, or play a MIDI keyboard after enabling it in **Settings › MIDI input**.
3. **Find a sound.** In the synth panel, click a preset to hear it and double-click to load it, or press **New generation from current** in the evolve section to hear nine variations of the current sound. Undo (Ctrl+Z) always takes a change back; Redo is Ctrl+Shift+Z or Ctrl+Y.
4. **Make a pattern.** Open the **Channel rack** (F6) and click steps, or the **Piano roll** (F7) and draw notes. Press **Play** (Space): pattern mode loops the selected pattern.
5. **Add effects.** Open the **Mixer** (F9), pick the channel's strip, press **+ Add effect** and type a name (try *Reverb* or *Delay*). Click the effect to open its editor.
6. **Arrange.** Switch to **Song**, add a playlist track with **+ Track**, and click in its lane to place the pattern. Drop an audio file on a lane to use it as an audio clip.
7. **Save and export.** **Ctrl+S** saves the project (a folder ending in `.rawdawg`). **File › Export…** renders WAV or FLAC, with optional stems.

## Starting

```sh
rawdawg                          # installed package: GUI with the default audio device
cargo run --release -p rawdawg   # from source
rawdawg --help                   # all options
```

Options:

| Flag | Effect |
|---|---|
| `--open <PATH>` | Open a project folder (`Something.rawdawg`), its `project.json` or its `project.rawdawg` marker; or import a `.rawdawgpreset` into a new project. |
| `--no-audio` | Start without opening an audio device (editing and offline render still work). |
| `--device <ID>` / `--buffer <FRAMES>` | Choose the output device (ids from `--list-audio-devices`) and request a buffer size. The status bar shows the actual negotiated configuration. |
| `--safe-mode` | Start without loading any third-party plugin; projects that use them keep their state in placeholders. |
| `--scan-plugins` | Scan the plugin folders into the catalog (each module in its own process) and print a JSON report. |
| `--list-audio-devices` | Print hosts and devices as JSON and exit. |
| `--audio-smoke` / `--capture-smoke` | Open the output (play a 1 s A4) or the input (capture 1 s), print the statistics and exit. |
| `--headless-render <PROJECT> --output <FILE>` | Render without GUI or audio device to `.wav` or `.flac`. Options: `--mode pattern|song`, `--format pcm16|pcm24|float32|flac16|flac24`, `--stems <DIR>`, `--tail <s>`, `--sample-rate <Hz>`, `--start-tick`, `--end-tick`, `--unprotected` (bypass master protection). |

Exit codes: 0 ok, 2 usage/IO error, 3 render reported engine health counters, 4 no usable device, 5 device opened but audio did not flow.

## Playing

The window opens with a playable **rawDAWg Synth** channel. Hold keys on the **typing keyboard** (toggle in the toolbar):

```
 S D   G H J   L ;      ← black keys
Z X C V B N M , . /     ← white keys: C D E F G A B C D E
```

`Octave −/+` shifts the base octave (default C4), `Velocity` sets note velocity. Keys are ignored while a text field has focus or when Ctrl/Alt is held; releasing focus releases the notes. **Panic** sends all-notes-off. While typing keys are on, S plays C# everywhere (it does not split playlist clips; use **Split at playhead** or the clip's menu).

The toolbar shows the keys you are holding, by name (middle C is C4), and the chord they form, for example `C4 Eb4 G4 · Cm` or `C4 G4 · C power` (typing keys, a MIDI keyboard or the on-screen piano). The playhead's bar and beat show there too, also with audio off; when audio starts it starts from that position. The same keys light up on the piano roll's keyboard (with their rows) and on the on-screen piano.

### Shaping the sound

The synth panel starts with the basics:

- **Oscillators**: **Start from** gives a fresh sound from one wave (**Sine**, **Saw**, **Square**, **Triangle**) or a stack (**Saw + Square**, **Saw octaves**: a saw with copies one and two octaves up, **Detuned saws + sub**: two saws 7 cents apart and a sine an octave below). Each row is one oscillator: switch it on or off, pick its **Waveform**, its **Octave** (− / +), **Detune** in cents (±100) and **Level** in percent. **+ Oscillator** adds a copy of the last one an octave higher, up to three; **×** removes one. Every change is one undo step; detune and level move live while you drag. A layer louder than 100 % (from a preset or Randomize) keeps its level when you touch its slider: the scale then reaches its level.
- **Amplitude envelope** (ADSR): drag the points on the curve (the attack peak sets the attack time, the end of the decay sets the decay time and the sustain level, the end of the sustain sets the level, the end sets the release time) or use the **Attack**, **Decay**, **Sustain** and **Release** sliders under it. A point stays under the pointer while you drag it, the values update as you go and each drag is one undo step. Each time segment has its own part of the width on a fixed scale (finer for short times, up to 30 s), so a longer time always means a point further right.
- The wave editor's **Harmonics** tab builds the selected oscillator's wave from harmonics: choose how many (1 to 64, **−**/**+** or type), then click or drag over the bars to set each harmonic's level (right-drag turns them off); the bar under the pointer shows its level in percent and dB, and the wave above follows. **Sine**, **Saw**, **Square** and **Triangle** fill the bars with that shape's series; **Randomize harmonics** picks random harmonics at random levels (the fundamental always stays, so the note keeps its pitch). Changing the count only changes how many bars you see; the wave changes at your next edit, which keeps only those harmonics (a wave with more, such as one drawn with the brushes, says so). Editing turns a plain oscillator into a drawn wave. Each edit is one undo step.

Transport: **Play** runs the selected pattern in a loop (pattern mode), **Stop** returns to the start. The status bar shows master meters, limiter activity, voice count, device, sample rate, CPU load and xruns.

### Finding sounds

**Randomize sound** gives the synth a new sound (a different one each time, also after a restart); **Chaos** sets how far it may stray (0 = small nudges, 100 = anything), and **Locks** keep categories you like (for example the envelope or the effects) untouched. **Evolve** makes nine variations of the current sound with **New generation from current**: click a card to hear it on the keyboard, **Use sound** keeps it (one undo step), **Compare parent** plays the sound they came from and **Cancel preview** goes back. **Evolve selected** breeds the next generation from the card you picked; Ctrl+click a second card and **Breed selected two** to mix two. **◀ Previous** and **Next ▶** walk through earlier generations, **★ Favorite** remembers a card. With **Match levels** on (the default) every variation plays about as loud as the sound you started from, by at most 12 dB either way, so a louder card does not just sound better; the small "preview" readout shows the correction. It is for listening only: **Use sound** keeps the variation at its own level. **XY Morph** stores the current sound in four corners; drag on the pad to blend between them while a note plays, **Freeze as current sound** keeps the blend, and **Write gesture as automation** turns a recorded movement into automation. Corners with different structures (other layer kinds or counts) cannot be blended into one sound: **Crossfade them in a morph rack** (or **Morph rack** for any four corners) replaces the channel's synth with a **morph rack**, which plays all four sounds on every note and crossfades them by its pad. Its **Morph X** and **Morph Y** work like any parameter: right-click them for an automation clip or MIDI learn, or move the pad during playback in Touch/Write mode to record them. The four corners together must fit what one synth may play (voices × unison); if they do not, rawDAWg says so instead of approximating. **Corner A…D as a synth** turns the rack back into one of its sounds; Undo works throughout.

In the **Advanced** view every control shows the value it stands for: **Transpose** and a layer's **Coarse** in semitones (`+0 st`, type `12` for an octave up), **Voices** and **Unison** as counts, and the choices (Filter Type, Voice Mode, Wave, Generator, FM Algorithm, LFO Shape…) by name. The exported rawDAWg Synth gives other hosts the same names and values.

### Modular graph (Advanced)

Tick **Advanced** in the synth panel and open **Modular graph**. The **voice graph** runs once per note between the layers and the filter/amp stage; the **global graph** runs once on the summed voices before the master gain. Both start as **Off** (the sound passes straight through) — press **Start graph** to get the fixed in/out nodes connected directly, then **+ Add node** (type to search). Drag from an output dot to an input dot to connect; colours mark the port type (teal audio, blue stereo, yellow control, pink event) and a mono output may feed a stereo input. Drag titles to move nodes, right-click a node or the small handle on a connection to delete it, scroll to pan and Ctrl+scroll to zoom. Every change is applied and audible immediately and is one undo step. If a change is not valid (a type mismatch, an instantaneous cycle, a budget overrun or an expression error) the editor shows the reason in red, highlights the offending edge or nodes and keeps the last valid graph playing. Feedback is only possible through a **Delay (feedback)** node, which reads at least 64 samples behind and limits the loop gain; such connections are drawn in orange. The **Expression** node evaluates a bounded formula per sample (`x`/`in1..in4` audio inputs, `ctrl1..ctrl4` control inputs or the node's own values, `t`, `phase`, `sr`; `+ - * /`, comparisons, `min max abs sin cos tanh exp log clamp select`), limited to 256 instructions; invalid divisions or logarithms give a finite value and are counted in the status line. The fixture project `fixtures/demo-graph.rawdawg` shows a complete example.

## Sequencing

**Pattern / Song** in the second toolbar row chooses what Play runs: the selected pattern in a loop, or the playlist. **Loop** repeats the pattern, the loop range or the song. The pattern selector creates (`+`), renames and resizes patterns (`…`, left or right click: 1/2/4/8 bars, step size 1/4…1/32); drawing a note past the end of a pattern also makes it longer, to the bar the note ends in (up to 128 bars). The **BPM** field in the toolbar sets the song's tempo: drag it, or click and type a value (20–400).

**Channel rack (F6)**: **+ Synth** adds a new rawDAWg Synth channel (the default sound, with its own mixer channel) below the selected one; clicking **rawDAWg Synth** in the browser does the same. Each channel shows step buttons for the selected pattern. Click toggles a step, drag paints, right-click sets the step's velocity and pitch. Notes that are not on the grid show an orange marker and a count; they are never moved by the step view. Drag a channel by its grip (the three lines at the left of its row) to move it up or down the rack; a line shows where it lands. The **…** button (left or right click) renames the channel (type, then Enter), **Duplicates** it (same sound and settings, placed right below, named "Lead 2", "Lead 3", …), **Duplicates with notes** (the copy also gets the channel's notes in every pattern), moves it up or down, or deletes it. Each of these is one undo step.

**Piano roll (F7)**: click in the grid to draw a note (drag while drawing to set its length), drag a note to move it, drag its right edge to resize, right-click to delete, right-drag to erase. Shift adds to the selection, Ctrl+drag (or the Select tool) box-selects. Delete removes, Ctrl+D duplicates after the selection, Ctrl+C/X/V copy/cut/paste at the playhead, arrows nudge by the grid or a semitone (Shift: octave), Escape cancels a gesture. Snap offers bar, beat, 1/2…1/32 and triplets (Alt bypasses). **Chord** inserts chords at the pointer, **Scale** highlights a scale and **Scale snap** keeps notes on it, **Quantize…** moves the selected (or all) notes toward the grid with a strength slider and an audible preview; nothing changes until you press Apply. The velocity lane below the grid draws or ramps velocities; an expression lane appears when the lane holds recorded pitch bend, CCs or sustain.

**Playlist**: `+ Track` adds a track; click in a lane to place the selected pattern (drag to paint repeats), drag clips to move them (Ctrl copies), drag their edges to trim/resize, S or "Split at playhead" splits, "Make unique" clones the pattern so later edits stay local, right-click a clip for mute/loop/make unique/open/split/delete; **Split here (bar …)** in that menu splits the clip where you right-clicked. A split never changes what you hear: the right half of an audio or automation clip continues from the split (a split after a sample has ended just trims the clip). Drag on the ruler to set the loop (and export) range; click it to move the playhead (with audio off too, so splitting at the playhead works without a device). Tempo and time-signature markers above the lanes open their editor on a click (type or drag the value, then Apply) and are added by right-clicking the marker row: the change lands in the bar you right-clicked, which the menu names.

**Expressive controllers**: the rawDAWg Synth plays each note's own expression. Polyphonic aftertouch and per-note pressure feed the **Aftertouch** modulation source of that note only (channel pressure feeds every note on its channel), and MPE controllers work: each note's pitch bend and pressure arrive on its own MIDI channel. For their third dimension (CC 74, "timbre"), switch on **CC 74 → brightness (MPE)** in the synth's parameters; it is off by default because many MIDI files and knobs use CC 74 for other things. CC 74 and a note's brightness move the filter cutoff up to two octaves either way (the filter must be on). As a plugin in another host, the synth also follows CLAP and VST3 note expressions: volume, pan, tuning, vibrato, expression and brightness (and pressure in CLAP); changes glide over a few milliseconds, so they never click.

**Recording**: arm **Rec**, choose a count-in (0–2 bars) and press Play or Space. Everything you play on the typing keyboard or a MIDI device while the transport runs is recorded into the selected pattern (looping overdubs on every pass); in Song mode a new "Take" pattern is placed as a clip where you started. Raw timing is kept; the recorded notes are selected afterwards so **Quantize…** can snap them when you want. The ms offset compensates input latency.

**Automation**: right-click any parameter → "Create automation clip". Curves live on an Automation track and play in Song mode; the Automation view edits points (click adds, drag moves, right-click deletes; per point Linear or Step) in the parameter's own units. Modes: Read plays, Touch writes while you hold a control during playback, Write latches the last value until you stop. The morph pad's "Write gesture as automation" bakes a recorded XY movement into curves. **MIDI learn** is in the same context menu: pick it, move a controller, done. A learned controller also records into an armed curve: in Touch mode while you turn it (the touch ends when the knob rests), in Write mode until playback stops. **Automate in this pattern** (same menu) makes a curve that belongs to the selected pattern instead: it spans the pattern, plays whenever the pattern plays (looping in Pattern mode, and inside each of the pattern's clips in Song mode, no automation clip needed), and Touch/Write record into it in both modes. Removing the pattern removes its curves (undoable); Make unique copies them.

**Browser**: the search box filters samples and effects; mark anything *+fav* to keep it at the top. *play* auditions a sample at a safe level through the master (audio must be on); clicking an effect adds it to the mixer channel selected in the Mixer view.

**Audio clips**: drop a `.wav`, `.flac` or `.mp3` onto a playlist lane and it becomes an audio clip right there (dropped anywhere else it becomes a sampler channel instead). Samples already in the project are listed in the browser: click one, then click a lane to place it (Esc cancels). Audio clips play in Song mode into the mixer channel chosen in the track header (Master by default), so inserts and sends apply to them like to anything else. Drag the right edge to shorten a clip, the left edge to trim its start; right-click it for gain and fade in/out. Tempo changes move clips but never stretch them.

## Mixer and effects

**Mixer (F9)**: the master is pinned on the left, other channels scroll. Each strip has mute, solo, pan, a fader with a dB readout (double-click resets), stereo meters with peak hold and a red clip bar (click to reset) and an output selector; `+ Bus` adds a channel. Right-click a strip's name to **Rename** or **Delete strip** (not the master): whatever played into it (rack channels, audio tracks, other strips) is rerouted to where the strip played, sends to it are removed, and the status bar says what moved; one Undo brings it all back. Deleting a channel in the rack also deletes its mixer strip when nothing else plays into that strip and it holds no effects (one undo step for both). Pick a strip to edit its **inserts** (`+ Add effect`, then search; Enter adds the first match; drag an insert by its grip (the three lines at the left of its row) to move it earlier or later in the chain, a line shows where it lands; bypass, wet/dry, up/down, remove; the reported latency is shown and compensated automatically so parallel paths stay aligned) and its **sends** (target, level, pre/post-fader, sidechain). Every channel in the rack chooses its mixer channel next to its name. The output latency created by effects is shown at the top of the mixer.

**Effects**: click an insert to open its editor. Each effect has presets, On/Bypassed, a Reset button, simple controls and an Advanced numeric view; right-click any control for MIDI learn or an automation clip. The **Parametric EQ** shows its response: click the plot to add a bell, drag a band to change frequency and gain, use the wheel over a band for Q, right-click a band to remove it, and choose each band's type below. The **Stereo** effect handles gain, pan, balance, width (mid/side), mono, channel swap and phase, and shows the stereo correlation. **Compressor**, **Limiter** and **Gate** show their gain reduction; the compressor and gate can listen to a sidechain send (enable "External sidechain" and send another channel to this bus with the sidechain switch on), and the limiter's true-peak mode watches inter-sample peaks (its lookahead is reported as latency and compensated). The **Delay** offers stereo, ping-pong, tape (wow and drive), multitap and reverse modes with a time in ms or synced to the tempo; in multitap mode drag the taps on the canvas (wheel pans, right-click toggles a tap), and reverse mode reports its segment length as latency. The **Reverb** has room, hall, cathedral, plate, spring and shimmer types; its decay-shape curve lets you drag each frequency band to ring longer or shorter than the decay time. **Convolution** uses an impulse response from your project assets (pick one, or type a path and press Import IR); long responses cost CPU. **Distortion** has tube (turn up Bias for an asymmetric, even-harmonic grit), tape, soft clip, hard clip, fold and bitcrush modes; raise Oversampling to tame aliasing on the clip and fold modes (the bitcrusher aliases on purpose: lower Bit depth and raise Rate divider for lo-fi). **Per-band distortion** splits the signal into four bands: drag across the Drive, Mix or Gain row on the canvas to paint each band (one undo step per stroke) and move the split frequencies below; untouched bands pass through unchanged. **Chorus**, **Flanger** and **Phaser** share a rate (or a tempo-synced division), sine/triangle shape and a stereo spread: the chorus layers up to four delayed voices, the flanger's feedback can go negative for a hollower comb, and the phaser sweeps 2 to 12 stages around its centre frequency. **Pitch / formant** shifts the pitch by semitones and cents without changing the length, moves the formants on their own (Chipmunk/Giant), or keeps them in place while the pitch moves (Preserve formants); it adds about 43 ms of latency, which the mixer compensates. **Spectral** works on the sound's spectrum: Freeze holds what is playing right now for as long as you like, Blur smears it over time, the gate keeps only the loudest partials, Tilt brightens or darkens per octave, Frequency shift slides every partial by the same number of hertz (inharmonic), and Robotise throws the phases away. **Granular** cuts the last two seconds of audio into grains: set their size and how many per second, how far back they are taken from (Position) and how much that wanders (Jitter), shift or scatter their pitch, play some backwards, spread them across the stereo field, and Freeze the buffer to keep playing what was captured.

**Presets**: every effect editor has *Preset file…* to save its settings as a `.rawdawgpreset` or load one; the mixer's *Rack preset…* saves a channel's whole insert chain and loads it onto any channel. Plugins from other vendors that are not available on this machine stay in the project as silent (instruments) or pass-through (effects) placeholders with their settings intact.

**Rack tools** (mixer, below the strips): **Randomize rack** changes every effect on the selected channel at once, as far as the **Chaos** slider allows; the **Locks** menu protects categories (wet/dry and output levels are locked by default), and one Undo takes the whole change back. **Morph**: store the rack's settings in corners A–D, then drag on the pad to blend between them (a drag is one undo step). **+ Parallel branch** makes a bus that receives a copy of the channel and sums back into the same output, so you can build a parallel effect path; the mixer keeps both paths aligned even when one of them adds latency. To move an effect parameter rhythmically, right-click it and pick **Modulate with an LFO clip**: a sine, triangle, square or saw automation clip appears, which you can edit like any other automation. Soloing a channel keeps the channels that feed its sidechain running (they stay out of the mix but still key the compressor).

## Recording audio

Open **Settings › Input (recording)**, tick *Open an input device*, choose the device and whether you record one input (mono) or a pair, then Apply. Press **R** in a playlist track's header to arm it, switch on **Rec**, and press Play in Song mode: the input is recorded from the moment the transport runs (after the count-in) and placed on that track as an audio clip when you stop, lined up with what you heard using the reported latencies plus the *Recording offset* (see "Measuring the latency" below). Monitoring the input through the master is off by default; do not switch it on while your interface already monitors directly, and keep speakers away from microphones. If rawDAWg stops unexpectedly during a take, the next open rebuilds the unfinished recording onto a “Recovered” track. While an input is open, an **In** level meter sits next to the recording offset in the toolbar and in the header of the armed track (the right-hand light turns red when the input reaches full scale; click it to reset).

**Measuring the latency.** Turn the **Metronome** on, connect an output of your interface to an input with a cable (or hold the microphone to a speaker), arm a track and record a few bars in Song mode. Right-click the take and choose **Measure recording latency** (or select it and use **Measure from the selected take** in Settings › Input): rawDAWg finds the clicks in the take and tells you how far they land from the beats. **Apply to new recordings** adds that to the recording offset, so later takes land on the beat. If the clicks are irregular (noise, no metronome, a missed click) it says so instead.

## Export and MIDI files

**File › Export…** renders the song (or the selected pattern) with the same engine you hear: pick WAV (16/24-bit or float) or FLAC (16/24-bit), the sample rate, a tail, and tick **Stems** for one file per mixer channel next to the mix. The export runs in the background with a progress bar and a Cancel button; when it is done you see the length, the peak and how many samples clipped (lower the master or export float if that number is not zero). Nothing is normalized. **Export MIDI (type 1)** writes the arrangement as a Standard MIDI File, or with **Scope: Pattern** only the selected pattern; if there are no notes to write it says so instead of writing an empty file. With **Range: Loop range** the MIDI file holds the loop range only, from its start (notes that begin inside it). The dialog shows the full paths it is about to write (the audio file, the MIDI file, the stems folder; a missing extension is added). A relative name is placed in the project folder, a folder gets a file named after the project, missing folders are created (`mixes/final` makes `mixes/`), and characters Windows does not allow in names are replaced. It asks before replacing any file that exists (**Replace** or **Keep the existing file**); while it asks, the settings are locked, and Replace writes exactly what it named. Replacing a stems folder removes the stems of the earlier export (numbered `NN-name` files) and leaves anything else in it. The output path belongs to the project: another project (also a new, never-saved one) proposes its own; a path you typed survives Save As. Dropping a `.mid` file on the window imports it: every MIDI track becomes a synth channel, the notes become a pattern placed on a new playlist track, and an empty project also takes the file's tempo and meter.

## Projects

A project is a folder ending in `.rawdawg` with `project.json` and the media you imported (copied in, named by content). **File › New…** starts an empty project in a working folder; **Save As…** writes a complete, independent copy to the folder you type (assets included, the previous folder stays as it was); **Open…** takes a folder or its `project.json` and lists recent projects (so does **Browser › Projects**); with unsaved changes, opening another project asks first (**Save and open**, **Discard and open**, **Cancel**). **Ctrl+S** saves in place (a project that was never saved asks for a folder, also when it already holds imported samples). In these dialogs **Enter** confirms and **Escape** cancels (Escape also closes Settings and the effect search). A new project is named after the folder of its first Save As (as is one still named after its old folder); **File › Rename project…** names it yourself (one undo step). The name proposes export file names and titles exported MIDI files. A song you open starts at bar 1. The File menu shows when the last autosave happened (its file on hover). Recent projects are remembered by their full path, so they open whichever folder rawDAWg was started from. While you have unsaved changes rawDAWg autosaves every two minutes into the project's `recovery` folder; if it ever stops unexpectedly, the next open offers to recover those changes (or keep the saved version, or discard the autosaves), also when the song had been saved and reopened before. A project that was never saved autosaves into your per-user data folder (`unsaved/`); if rawDAWg stops unexpectedly, the next start offers it back (**Recover**, then **Save As** to keep it; **Not now** asks again at the next start; **Discard autosaves**). Work you discard on purpose (Discard, New project, closing without unsaved changes) is not offered. **Compare** lists what the autosave changes (notes, sounds, channels, the playlist, the mixer, automation) and lets you **Listen to** the saved version or the autosave with Play before you choose; with several autosaves you pick which one. A project opened in two places at once (from File › Open, the Projects list or `--open`) is read-only in the second until you take over the lock; the project you leave is released. If a sample file is missing from the folder the browser says so and lets you relink it: the same file restores it, a different file replaces it everywhere (undoable). Closing with unsaved changes asks whether to save; on a project that was never saved, **Save and close** opens Save As first and closes once that save succeeds (Cancel keeps rawDAWg open).

## Plugins

**Third-party CLAP and VST3 plugins.** Open **Settings › Plugins** and press **Scan plugin folders**. rawDAWg looks in the standard locations (CLAP: `~/.clap`, `/usr/lib/clap`, `/usr/local/lib/clap` and `CLAP_PATH` on Ubuntu, `%COMMONPROGRAMFILES%\CLAP` and `%LOCALAPPDATA%\Programs\Common\CLAP` on Windows; VST3: `~/.vst3`, `/usr/lib/vst3`, `/usr/local/lib/vst3`, `%COMMONPROGRAMFILES%\VST3`, `%LOCALAPPDATA%\Programs\Common\VST3`) plus the extra folders you add there. VST3 plugins are found as `.vst3` bundles or bare modules; only VST3 plugins that accept stereo 32-bit float buses are hosted (others stay stand-ins with the reason shown). Every module is examined in a **separate scanner process** with a timeout (15 s by default, adjustable): a module that crashes, hangs or fails to load is **quarantined** and listed with the reason; **retry** scans it again next time, **remove** forgets it. The catalog lives in your preferences folder (`plugins.json`), not in projects.

Scanned plugins appear in the browser under **Plugins** (search by name, vendor or id) and in the mixer's **+ Add effect** list with a `(CLAP)` or `(VST3)` suffix. Clicking an effect adds it as an insert on the selected mixer channel; clicking an instrument replaces the selected channel's instrument (undo restores the old one). The effect/instrument panel shows the plugin's parameters in rawDAWg's generic editor, with the plugin's own value text (for example `322.2 ms` or `-6.0 dB`, as the plugin formats it) and a named list for parameters with a few choices (up to 64); automation lanes show the same text. **Bypass** keeps the chain's latency aligned, automation and MIDI learn work as for native effects. A plugin's own state is saved inside the project (larger states as files in the project's `plugin-state/` folder; keep that folder with the project); a project that references a plugin you do not have opens with a **stand-in** (effects pass audio through, instruments stay silent) and keeps the state untouched until the plugin is available again.

Third-party plugins run inside rawDAWg as native code: the scanner isolation is crash containment for discovery, not a sandbox. If rawDAWg ends without a clean shutdown while plugins were loaded, the next start says so in Settings › Plugins; restart with `--safe-mode` to open projects without loading any third-party plugin (they are listed but never instantiated). Plugin blocks that produce errors or non-finite output are muted and counted in Settings › Plugins. **Plugin windows**: a hosted CLAP or VST3 plugin with its own editor gets an **Open plugin window** button in its panel; the editor opens in its own window (X11/XWayland on Ubuntu, Win32 on Windows). Changes you make there are stored in the project once you pause (one undo step) and when you close the window. Plugins whose editor rawDAWg cannot embed say so and stay editable in the panel.

`rawdawg --scan-plugins [--catalog FILE]` runs the same scan from the command line and prints a JSON report.

**rawDAWg as a plugin.** The build produces real plugin binaries in `target/<profile>/`:

- `librawdawg_clap.so` / `rawdawg_clap.dll` — one CLAP module containing **rawDAWg Synth** (`rawdawg.synth`: notes in, stereo out) and every effect family as its own plugin (`rawdawg.fx.eq`, `rawdawg.fx.compressor`, `rawdawg.fx.limiter`, `rawdawg.fx.gate`, `rawdawg.fx.distortion`, `rawdawg.fx.multiband`, `rawdawg.fx.delay`, `rawdawg.fx.chorus`, `rawdawg.fx.flanger`, `rawdawg.fx.phaser`, `rawdawg.fx.pitch`, `rawdawg.fx.granular`, `rawdawg.fx.spectral`, `rawdawg.fx.reverb`, `rawdawg.fx.convolution`, `rawdawg.fx.stereo`; display names **rawDAWg Parametric EQ**, **rawDAWg Reverb**, …). Effects take stereo in/out, report latency and tail, follow the host tempo, and add **Bypass** and **Mix** parameters. Parameters with whole-number steps (modes, sync divisions, voice counts, lookahead) are published as those steps, so every choice is reachable in other hosts; the rest are 0–1 values with rawDAWg's readout text; the compressor and gate expose a stereo **Sidechain** input. Rename/copy the module to `rawDAWg.clap` for hosts that require the extension. Each plugin has an **editor** (the rawDAWg wordmark, the plugin's name and every parameter with the same controls as in rawDAWg) that hosts embed on Ubuntu (X11; the host must offer CLAP timer support, as common hosts do) and Windows; edits are reported to the host with gestures, so it records automation. Effect presets saved from the app load as plugin state. The convolution plugin has no impulse response outside a rawDAWg project yet (it passes the dry signal).
- `librawdawg_vst3.so` / `rawdawg_vst3.dll` — the same 17 plugins as a VST3 module (stable class ids recorded in `crates/plugin-api`): stereo main in/out, aux **Sidechain** bus for the compressor and gate, event bus for the synth, sample-accurate parameter queues, process context (tempo, transport, time signature), latency and tail, the same **Bypass**/**Mix** wrapper parameters and the same state envelope as the CLAP version (a preset saved in one format loads in the other). `cargo xtask verify` lays it out as `target/verification/bundles/rawDAWg.vst3/Contents/<arch>/` with a `moduleinfo.json`; copy that folder into your VST3 directory. The same editor as the CLAP version (`IPlugView`; on Ubuntu the host must offer the VST3 run loop, as VST3 hosts on Linux do); parameter changes go to the host through its component handler, so it records automation.

Each plugin opens its own editor window in the host with the same controls as in rawDAWg. The **EQ** window shows its response: click empty space to add a band there, drag a band for frequency and gain, use the wheel over a band for Q and right-click to switch it off. The **Synth** window shows the amp envelope (drag the peak for attack, the sustain point for decay and sustain, the end for release) and the filter curve (drag its handle left/right for cutoff, up/down for resonance). The synth also takes per-note expression from hosts that send it (see "Expressive controllers").

Validation with `clap-validator`, the VST3 validator and independent hosts is tracked as open gates in `PROGRESS.md`.

## Installing

- **Ubuntu 24.04**: `sudo dpkg -i rawdawg-<version>-x86_64.deb` (dependencies: libasound2, glibc). Installs `rawdawg`, a desktop entry that opens projects (double-click the `project.rawdawg` file inside a project folder) and `.rawdawgpreset` presets (double-click imports the sound into a new project), and the rawDAWg CLAP/VST3 plugins into `/usr/lib/clap` and `/usr/lib/vst3` for other hosts. `sudo apt remove rawdawg` keeps your projects and preferences.
- **Windows 11**: run `rawdawg-<version>-x86_64.msi` (per-machine, unsigned: Windows will warn), or unzip the portable build and run `rawdawg.exe` from the folder. The installer registers `.rawdawg` (the `project.rawdawg` marker in each project folder) and `.rawdawgpreset`, and puts the plugins into the common CLAP/VST3 folders.
- **From source**: see `README.md` (pinned toolchain, `cargo build --workspace --release --locked`).

A project is a folder (`Song.rawdawg/`); every save writes a small `project.rawdawg` marker into it, and that file is what the desktop opens. **File › Open**, the recent-projects list and `rawdawg --open <folder>` work too. rawDAWg works offline; nothing phones home.

## Troubleshooting

- **"Audio unavailable"** in the status bar: no output device could be opened. Check `rawdawg --list-audio-devices`, pick a device in **Settings › Audio**, then **Apply** (or **Retry audio** in the status bar; **Start audio** when audio was turned off). A long error is cut in the status bar; point at it for the whole text. Everything except playback keeps working.
- **Crackles or rising xrun count**: raise the buffer (**Settings › Audio**, or `--buffer 512`), lower the synth's voice count, or bypass heavy effects (Reverb, Spectral and Pitch cost the most; Convolution with a long impulse response too). Under WSL or a virtual machine, occasional slow blocks come from the environment as well.
- **MIDI timing**: notes from a MIDI device are placed by the device's own timestamps at a steady latency (about two audio buffers plus the time rawDAWg needs to pick them up, at most two buffers plus 40 ms), so a fast phrase keeps its rhythm instead of being bunched to the audio blocks. A smaller buffer means less latency. The status bar shows "late MIDI" with a count when something held rawDAWg up so long that notes could not be placed in time.
- **No sound from a MIDI keyboard**: enable the device in **Settings › MIDI input** (on Ubuntu the user must be allowed to open ALSA sequencer devices; under WSL there is usually no MIDI at all). The status bar's MIDI counter shows how many messages arrive.
- **Notes ring on after Stop**: long synth releases keep sounding until they fade; **Panic** silences everything at once.
- **rawDAWg closed unexpectedly**: reopen the project; if autosaved changes are newer than the saved file, rawDAWg offers to recover them. An unfinished audio take is rebuilt onto a “Recovered” track. If third-party plugins were loaded at the time, **Settings › Plugins** says which; start with `--safe-mode` if the crash repeats.
- **"Project is open elsewhere" / read-only**: the project is locked by another rawDAWg window (or by one that crashed). Close the other window, or take over the lock when asked.
- **A sample is missing**: the browser marks it; **Relink** and pick the same file (or a replacement, applied everywhere and undoable). The clip or sampler stays silent until then.
- **A plugin shows as a stand-in**: it is not in the catalog, quarantined, or you started in safe mode. The reason is in the status line and the panel; scan your plugin folders in **Settings › Plugins**. Its state stays in the project untouched. If the reason says its *saved state file is missing or damaged*, the file in the project's `plugin-state/` folder is gone or changed (for example the project was copied without that folder): put the folder back and reopen; rawDAWg never replaces the saved state with defaults. The same applies when a plugin cannot restore its saved state.
- **A plugin module is quarantined**: it crashed, hung or did not load during the scan. **retry** scans it again next time; nothing from it is loaded until then.
- **Double-clicking a project folder does not open it**: folders cannot be associated with an app; open the `project.rawdawg` file inside the folder instead (installed packages register it), or use **File › Open…**.
- On Ubuntu, ALSA is the baseline; JACK and PipeWire backends are compile-time features (`--features jack` / `pipewire`) that need the corresponding development packages.
